# Սխալներ և մեկնաբանություններ․ ինչպե՞ս արդյունավետ օգտագործել utop-ը

[Նախորդ հոդվածում](./2026-11-18-ocaml-variable-binding.md) առաջին անգամ տեսանք սխալի մասին հաղորդագրություն՝ `Unbound value`։ Ծրագիր գրելիս սխալվելը բնական է։ OCaml-ի հաղորդագրություններն օգնում են հասկանալ, թե ինչ խնդիր է առաջացել և կոդի որ մասում։ Այս անգամ կսովորենք կարդալ այդ հաղորդագրությունները և գրել մեկնաբանություններ։ Կփորձենք նաև utop-ի մի քանի հնարավորություն, որոնք կօգնեն խուսափել նույն կոդը նորից մուտքագրելուց։ Ինչպես նախորդ անգամ, բաց պահեք utop-ը և հերթով փորձեք օրինակները։

## Երբ OCaml-ը մերժում է կոդը

OCaml-ը ստուգում է ձեր մուտքագրած կոդը նախքան այն կատարելը։ Եթե սխալ է գտնում, ոչինչ չի կատարում և արտածում է `Error:`-ով սկսվող հաղորդագրություն։ utop-ը նաև ընդգծում է կոդի այն մասը, որին վերաբերում է հաղորդագրությունը։

### Տիպերի անհամապատասխանության սխալներ

```ocaml
1 + "2";;
```

```text
Error: This constant has type string but an expression was expected of type int
```

_Հաստատունը_ (_constant_) անմիջապես կոդում գրված արժեք է, օրինակ՝ `42` կամ `"2"`։ Հաղորդագրությունն ասում է․ «Այս արժեքի տիպը `string` է, իսկ այստեղ OCaml-ն ակնկալում էր `int` տիպի արտահայտություն»։ `+` օպերատորը գումարում է ամբողջ թվեր։ Իսկ `"2"`-ը գրված է կրկնակի չակերտների մեջ, ուստի այն տեքստային արժեք է։ Սա **տիպերի անհամապատասխանության սխալ** է (_type error_)․ մի տիպի արժեք ենք օգտագործել այնտեղ, որտեղ այլ տիպի արժեք է պահանջվում։ Եթե չակերտները հանենք ու գրենք `1 + 2;;`, OCaml-ը կգումարի երկու թվերը։

### Շարահյուսական սխալներ

```ocaml
(1 + 2;;
```

```text
Error: Syntax error: ')' expected, the highlighted '(' might be unmatched
```

**Շարահյուսական սխալը** (_syntax error_) նշանակում է, որ OCaml-ը չի կարողանում հասկանալ կոդի կառուցվածքը․ ինչ-որ բան բացակայում է կամ սխալ տեղում է գրված։ Այս օրինակում բաց ենք թողել փակող փակագիծը։ utop-ն ընդգծում է բացող `(` փակագիծը և `;;`-ը։ Հասնելով `;;`-ին՝ OCaml-ը դեռ սպասում էր `)`-ին։ Երբեմն հաղորդագրության մեջ գրված է միայն `Syntax error`։ Այդ դեպքում ստուգեք ընդգծված հատվածը և դրանից անմիջապես առաջ գրվածը։

### Տառասխալներ

Եթե անունը տառասխալով գրեք, կստանաք նախորդ հոդվածից ծանոթ հաղորդագրությունը։ Փորձենք, օրինակ, OCaml-ի ստանդարտ գրադարանի ֆունկցիայի անունից բաց թողնել վերջին տառը։

```ocaml
print_endlin "Hi";;
```

```text
Error: Unbound value print_endlin
Hint:   Did you mean print_endline?
```

## Բացառություններ․ երբ խնդիրը ծագում է կոդը կատարելիս

```ocaml
10 / 0;;
```

```text
Exception: Division_by_zero.
```

Նախորդ հաղորդագրությունները սկսվում էին `Error:`-ով, իսկ այս մեկը՝ `Exception:`-ով։ Տիպերի հետ խնդիր չկա․ `10` և `0` արժեքները երկուսն էլ `int` տիպի են։ Ուստի OCaml-ն ընդունում է կոդն ու սկսում հաշվել արտահայտության արժեքը։ Բայց ամբողջ թիվը զրոյի չի բաժանվում։ Հաշվարկն ընդհատվում է, և OCaml-ը հայտնում է առաջացած **բացառության** (_exception_) մասին։ Նախորդ օրինակների սխալները OCaml-ը հայտնաբերում է մինչև կոդը կատարելը, իսկ բացառությունն առաջանում է կատարման ընթացքում։

Երկու դեպքում էլ utop-ը շարունակում է աշխատել։ Կարող եք նոր արտահայտություններ մուտքագրել և օգտագործել ավելի վաղ սահմանած անունները։

## Մեկնաբանություններ

**Մեկնաբանությունը** (_comment_) կոդը կարդացողի համար գրված նշում է։ OCaml-ն այն անտեսում է։ Մեկնաբանության սկիզբը նշում ենք `(*`-ով, իսկ վերջը՝ `*)`-ով։

```ocaml
1 + 2 (* this part is ignored *);;
```

```text
- : int = 3
```

Մեկնաբանությունը կարող է մի քանի տող զբաղեցնել և դրա ներսում կարելի է գրել նաև մեկ այլ մեկնաբանություն։

```ocaml
(* outer (* inner *) still outer *) 5;;
```

```text
- : int = 5
```

Եթե ուզում եք, որ կոդի որևէ հատված ժամանակավորապես չկատարվի, դրա սկզբում գրեք `(*`, իսկ վերջում՝ `*)`։ Դա կարող եք անել նույնիսկ այն դեպքում, երբ այդ հատվածում արդեն մեկնաբանություններ կան։ OCaml-ում մեկ տողի մեկնաբանության համար առանձին նշան չկա, ինչպիսին է `//`-ը C-ում կամ `#`-ը Python-ում։

Եթե մեկնաբանությունը չփակեք, դրան հաջորդող ամեն ինչ, նույնիսկ `;;`-ը, կհամարվի մեկնաբանության մաս։ Եթե մուտքագրեք `(* the area 1 + 2;;`, utop-ը չի պատասխանի․ այն դեռ սպասում է փակող `*)`-ին։ Նույնը տեղի է ունենում, եթե տեքստային արժեքը գրելիս բաց թողնեք փակող չակերտը (`"`)։ Եթե թվում է, թե utop-ը չի արձագանքում, սեղմեք Ctrl+C։ Կտեսնեք `Interrupted.` հաղորդագրությունը և մուտքագրման նոր տողը։

## utop-ի օգտակար հնարավորությունները

### Մուտքագրման պատմություն

Սեղմեք վերևի սլաքը (Up), և utop-ը ցույց կտա ձեր վերջին մուտքագրածը։ Կրկին սեղմեք այն՝ պատմության մեջ մեկ քայլ էլ հետ գնալու համար։ Ներքևի սլաքով (Down) կարող եք առաջ գնալ։ Տառասխալն ուղղելու ամենաարագ ձևը սա է․ Up-ով հետ բերեք տողը, ձախ ու աջ սլաքներով (Left և Right) անցեք անհրաժեշտ տեղը, ուղղեք սխալն ու սեղմեք Enter։ utop-ից դուրս գալիս մուտքագրման պատմությունը պահպանվում է, և utop-ը հաջորդ անգամ գործարկելիս էլի կարող եք օգտվել դրանից։

### Անունների ինքնալրացում

[utop-ի մասին առաջին հոդվածում](./2026-11-17-ocaml-first-steps-in-utop.md) մուտքագրման տողի տակ մի շարք անուններ տեսանք։ Դրանք հայտնվում են **ինքնալրացման գոտում** (_completion bar_)։ Այնտեղ երևում են այն անունները, որոնք սկսվում են ձեր մուտքագրած նիշերով։ Մուտքագրեք `print_`, և կտեսնեք արտածման ֆունկցիաների անունների հուշումները։

```text
print_bytes  print_char  print_endline  print_float  print_int  print_newline  print_string
```

Այժմ գրեք `print_end` և սեղմեք Tab։ Այդպես սկսվող միայն մեկ անուն կա, և utop-ն ամբողջացնում է այն՝ `print_endline`։ Երբ մի քանի անուն է համապատասխանում, Tab-ը լրացնում է միայն դրանց ընդհանուր սկզբնամասը։ Ինքնալրացման գոտում Alt+Right և Alt+Left համակցություններով կարող եք անցնել մի անունից մյուսը։ Երբ հասնեք ցանկալի անվանը, հաստատեք ընտրությունը Alt+Down-ով։ macOS-ում Alt-ին համապատասխանում է Option ստեղնը։ Որոշ տերմինալներում այս համակցություններն օգտագործելու համար պետք է միացնել «Use Option as Meta key» կամ այլ համարժեք կարգավորում։

### Բազմատող մուտքագրում

utop-ը կատարում է ձեր մուտքագրած կոդը միայն այն ժամանակ, երբ վերջում `;;` կա։ Եթե առանց `;;` գրելու սեղմեք Enter, utop-ը կսպասի հաջորդ տողին։ Այսպես երկար արտահայտությունը կարող եք գրել մի քանի տողով։

```ocaml
if 3 > 2
then "yes"
else "no";;
```

```text
- : string = "yes"
```

### Օգտակար ստեղներ

| Ստեղն կամ համակցություն       | Գործողություն                                                |
| ----------------------------- | ------------------------------------------------------------ |
| Up, Down                      | Ցուցադրել պատմության նախորդ կամ հաջորդ գրառումը              |
| Ctrl+R                        | Որոնել մուտքագրման պատմության մեջ                            |
| Tab                           | Ինքնաբերաբար լրացնել անունը                                  |
| Alt+Left, Alt+Right, Alt+Down | Ինքնալրացման գոտում ընտրել անունը և հաստատել ընտրությունը    |
| Ctrl+C                        | Չեղարկել ընթացիկ մուտքագրումը                                |
| Ctrl+L                        | Մաքրել էկրանը                                                |
| Ctrl+D                        | Դուրս գալ utop-ից (եթե հրահանգի տողում ոչինչ մուտքագրված չէ) |

## Անմիջապես utop-ին ուղղված հրահանգներ

utop-ի մուտքագրման տողում կարող ենք մուտքագրել `#`-ով սկսվող հրահանգ (_directive_)։ Այն ուղղված է հենց utop-ին և OCaml-ի սովորական կոդի մաս չէ։ [Միջավայրի կարգավորման մասին հոդվածից»](./2026-11-15-ocaml-development-environment.md) արդեն գիտեք `#quit;;` հրահանգը։ Ահա ևս երկուսը, որոնք կարող եք անմիջապես փորձել։

- `#utop_bindings;;` հրահանգը ցույց է տալիս utop-ի բոլոր ստեղնաշարային համակցությունները
- `#use "file.ml";;` հրահանգը կարդում է ֆայլը և կատարում դրա կոդը [այնպես, կարծես այն մուտքագրել եք անմիջապես utop-ում](https://ocaml.org/manual/latest/toplevel.html)

### Ֆայլի գործարկում `#use` հրահանգով

Ստեղծեք `rectangle.ml` անունով ֆայլ, օրինակ՝ այն պանակում, որտեղ միջավայրը կարգավորելիս պահել էիք `hello.ml` ֆայլը։

```ocaml
(* The size of a room, in meters *)
let width = 8
let height = 5

(* The area is width times height *)
let area = width * height
```

Ինչպես `hello.ml`-ում, այստեղ էլ տողերի վերջում `;;` դնելու կարիք չկա։ Այդ պանակում բացեք տերմինալը, գործարկեք `utop`-ը և բեռնեք ֆայլը։

```ocaml
#use "rectangle.ml";;
```

```text
val width : int = 8
val height : int = 5
val area : int = 40
```

Ինչպես և սպասվում էր, utop-ն անտեսեց մեկնաբանությունները։ Այժմ դուք կարող եք օգտագործել ֆայլում սահմանված անունները։ Մուտքագրեք `area;;`, և կստանաք `- : int = 40`։ Եթե utop-ը գործարկել եք մեկ այլ պանակում, որտեղ այդ ֆայլը չկա, կտեսնեք `Cannot find file rectangle.ml.` հաղորդագրությունը։

Այսպես հարմար է աշխատել․ կոդը գրում եք ձեր խմբագրիչում, ֆայլը բեռնում `#use` հրահանգով, ապա գրվածը փորձարկում utop-ում։ Ամեն փոփոխությունից հետո ֆայլը նորից բեռնեք `#use` հրահանգով։

## Ամփոփում

- `Error:` նշանակում է, որ OCaml-ը մերժել է մուտքագրված կոդը մինչև այն կատարելը։ Պատճառը կարող է լինել տիպերի անհամապատասխանության սխալ, շարահյուսական սխալ կամ անհայտ անուն։ `Exception:` նշանակում է, որ կոդի կատարումը սկսվել է և ընդհատվել բացառության պատճառով։
- Մեկնաբանությունը գրում ենք `(*` և `*)` նշանների միջև։ Այն կարող է մի քանի տող զբաղեցնել և իր մեջ այլ մեկնաբանություններ պարունակել։
- Up և Down ստեղներով կարող եք նորից օգտագործել ավելի վաղ մուտքագրածը։ Tab-ը լրացնում է անունը, իսկ եթե տողի վերջում `;;` չկա, Enter-ով կարող եք շարունակել հաջորդ տողում։ Ctrl+C-ն չեղարկում է ընթացիկ մուտքագրումը։
- `#`-ով սկսվող հրահանգներն ուղղված են utop-ին։ `#use "file.ml";;` հրահանգը կատարում է ֆայլի կոդն այնպես, կարծես այն մուտքագրել եք անմիջապես utop-ում։
