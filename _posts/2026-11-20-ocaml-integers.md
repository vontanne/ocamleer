# Ամբողջ թվեր․ թվաբանական գործողություններ և int տիպի սահմանները

Ամբողջ թվերին ծանոթ ենք դեռ նախորդ հոդվածներից։ Այս անգամ ավելի մանրամասն կծանոթանանք `int` տիպին․ կտեսնենք, թե ինչպես են գրվում ամբողջ թվերը և ինչ սահմաններում կարող են լինել դրանց արժեքները։ Բաց պահեք utop-ը և հերթով փորձեք օրինակները։

## Ինչպես գրել ամբողջ թվերը

Անմիջապես կոդում գրված ամբողջ թիվը, օրինակ՝ `42`-ը, կոչվում է **ամբողջ թվի լիթերալ**։ [Նախորդ հոդվածում](./2026-11-19-ocaml-errors-comments-utop.md) նման արժեքներն անվանեցինք _հաստատուններ_։ Երկու անվանումն էլ ճիշտ է․ OCaml-ի ձեռնարկում [ամբողջ թվի լիթերալը ներկայացվում է որպես հաստատունների տեսակներից մեկը](https://ocaml.org/manual/latest/const.html)։ Երբ թիվը շատ թվանշաններ ունի, դրանք կարելի է [բաժանել խմբերի՝ ընդգծման գծիկով](https://ocaml.org/manual/latest/lex.html#sss:integer-literals) (`_`)։ Այդպես թիվն ավելի հեշտ է կարդալ։ OCaml-ն անտեսում է գծիկները։

```ocaml
let population = 3_000_000;;
```

```text
val population : int = 3000000
```

## Օպերատորները և գործողությունների հերթականությունը

Ամբողջ թվերի հիմնական թվաբանական օպերատորներն են `+`, `-`, `*`, `/` և `mod` (բաժանման մնացորդ)։ `mod`-ը գրվում է բառով և մյուս օպերատորների պես դրվում է երկու թվերի միջև։ Օրինակ՝ `17 mod 5` արտահայտության արժեքը `2` է, քանի որ 17 = 3 × 5 + 2։

**Օպերատորների առաջնահերթությունը** որոշում է, թե որ գործողությունն է կատարվում առաջինը։ `*`, `/` և `mod` օպերատորներն ավելի բարձր առաջնահերթություն ունեն, քան `+` և `-` օպերատորները։ Այստեղ նույն առաջնահերթությունն ունեցող օպերատորները խմբավորվում են ձախից աջ։

```ocaml
10 + 7 mod 3;;
(10 + 7) mod 3;;
10 - 3 - 2;;
```

```text
- : int = 11
- : int = 2
- : int = 5
```

Վերջին տողում OCaml-ը հաշվում է `(10 - 3) - 2`։ Եթե գրեինք `10 - (3 - 2)`, կստանայինք `9`։ Երկար թվաբանական արտահայտություններ օգտագործելու դեպքում փակագծեր դրեք․ այդպես կոդը նաև ավելի հեշտ է կարդալ։ Ձեռնարկում նշված է [բոլոր օպերատորների առաջնահերթությունը](https://ocaml.org/manual/latest/expr.html#ss:precedence-and-associativity)։

## Բացասական թվեր

Թվի կամ այն ներկայացնող փոփոխականի անվան առջև դրված մինուսը փոխում է թվի նշանը։

```ocaml
let debt = 250;;
-debt;;
```

```text
val debt : int = 250
- : int = -250
```

Այստեղ մինուսը կիրառվում է մեկ արժեքի նկատմամբ և կոչվում է **ունար մինուս**։ Իսկ `10 - 3` արտահայտության մեջ մինուսը դրված է երկու արժեքի միջև, կոչվում է բինար մինուս և նշանակում է, որ առաջինից հանում ենք երկրորդը։ OCaml-ը մինուսի նշանակությունը որոշում է ըստ դիրքի։ Թվից, անունից կամ փակող փակագծից հետո `-` նշանը նշանակում է հանում։ Արտահայտության սկզբում կամ մեկ այլ օպերատորից անմիջապես հետո այն ունար մինուս է։

```ocaml
10 - -3;;
10--3;;
```

```text
- : int = 13
Error: Unbound value (--)
```

Երկրորդ տողում նշանների միջև բացատ չկա, ուստի OCaml-ը `--`-ը կարդում է որպես մեկ օպերատորի անուն։ Այդ անունով օպերատոր սահմանված չէ։ Երկու մինուսների միջև պետք է բացատ թողնել։

### Ինչո՞ւ չի աշխատում `abs -7` գրառումը

Ստանդարտ գրադարանի `abs` ֆունկցիան վերադարձնում է թվի բացարձակ արժեքը, այսինքն՝ նրա հեռավորությունը զրոյից։ Ինչպես `print_endline`-ի դեպքում, **արգումենտը**՝ ֆունկցիային տրվող արժեքը, գրում ենք ֆունկցիայի անունից հետո՝ բացատ թողնելով։

```ocaml
abs 7;;
abs -7;;
```

```text
- : int = 7
Error: The value abs has type int -> int but an expression was expected of type
         int
```

Քանի որ `abs`-ը անուն է (կոնկրետ այս օրինակում ֆունկցիայի անուն), դրան հաջորդող `-` նշանը նշանակում է հանում, ուստի OCaml-ը `abs -7` գրառումը կարդում է որպես `abs - 7`։ Սխալի հաղորդագրության մեջ `int -> int` գրառումը նշանակում է, որ ֆունկցիան ընդունում է `int` տիպի արժեք և վերադարձնում `int` տիպի արժեք։ Հանման նշանից ձախ OCaml-ն ակնկալում է `int` տիպի արժեք, իսկ այստեղ ֆունկցիա է։ Հետևաբար այսպիսի դեպքերում փակագծերի օգտագործումը պարտադիր է, դրանով մենք ցույց ենք տալիս, որ `-7`-ն ամբողջությամբ մեկ արգումենտ է։

```ocaml
abs (-7);;
```

```text
- : int = 7
```

## Ամբողջ թվերով և մնացորդով բաժանում

### Կլորացում դեպի զրո

Ամբողջ թվերի բաժանման ժամանակ քանորդի կոտորակային մասն անտեսվում է․ օրինակ՝ `7 / 2`-ը `3` է։ Նույնը տեղի է ունենում բացասական թվերի դեպքում․

```ocaml
-7 / 2;;
7 / -2;;
```

```text
- : int = -3
- : int = -3
```

Երկու դեպքում էլ ճշգրիտ քանորդը -3,5 է։ Երկու հարևան ամբողջ թվերից՝ -4-ից և -3-ից, OCaml-ն ընտրում է զրոյին ավելի մոտը՝ -3-ը։ Այս կանոնը կոչվում է **կլորացում դեպի զրո** (_truncation toward zero_)։ Քանորդի նշանը որոշվում է բաժանման սովորական կանոնով, իսկ բացարձակ արժեքը նույնն է, ինչ `7 / 2`-ի դեպքում։

### Մնացորդի նշանը

`/` և `mod` օպերատորները կապված են միմյանց հետ։ Ըստ [ստանդարտ գրադարանի փաստաթղթերի](https://ocaml.org/manual/latest/api/Stdlib.html)՝ զրոյից տարբեր ցանկացած `y`-ի համար ճիշտ է `x = (x / y) * y + x mod y` հավասարությունը։ Ուստի `x mod y` մնացորդը կա՛մ զրո է, կա՛մ ունի `x`-ի նշանը՝ անկախ `y`-ի նշանից։

```ocaml
-7 mod 3;;
7 mod -3;;
```

```text
- : int = -1
- : int = 1
```

Ամբողջ թվերով և մնացորդով բաժանման ժամանակ հեշտ է շփոթվելը, հատկապես եթե դուք աշխատել եք Python-ով, որտեղ ամբողջ թվի բաժանման արդյունքը [կլորացվում է դեպի ներքև](https://docs.python.org/3/library/stdtypes.html#numeric-types-int-float-complex), ուստի `-7 // 2`-ի արժեքը `-4` է, իսկ `-7 % 3`-ինը՝ `2`։

### Զրոյի վրա բաժանում

Երբ բաժանարարը զրո է, թե՛ `/`-ը, թե՛ `mod`-ն առաջացնում են `Division_by_zero` բացառություն։ Մինչև կոդը կատարելը OCaml-ը ստուգում է տիպերը, այլ ոչ թե արժեքները, ուստի տիպերի ստուգումն անցնում է նաև փոփոխականը, որին տրված արժեքը 0 է, իսկ բացառությունն առաջանում է ծրագրի աշխատանքի ժամանակ՝ հաշվարկի պահին։

```ocaml
let people = 0;;
120 mod people;;
```

```text
val people : int = 0
Exception: Division_by_zero.
```

## Ի՞նչ սահմաններ ունի int տիպը

Ստանդարտ գրադարանում `int` տիպի ամենամեծ և ամենափոքր արժեքներն իրենց անուններն ունեն։ Ահա թե ինչ է ցույց տալիս utop-ը 64-բիթանոց համակարգում։

```ocaml
max_int;;
min_int;;
```

```text
- : int = 4611686018427387903
- : int = -4611686018427387904
```

Երկու թվերի բացարձակ արժեքն էլ մոտ 4,6 × 10<sup>18</sup> է։ Ավելի ճշգրիտ՝ `max_int`-ը 2<sup>62</sup> - 1 է, իսկ `min_int`-ը՝ -2<sup>62</sup>։

### Ինչո՞ւ 64 բիթից միայն 63-ը

Համակարգիչները թվերը պահում են **բիթերով**։ Բիթը երկուական թվանշան է՝ 0 կամ 1։ Այսօր տարածված 64-բիթանոց համակարգիչներում հիշողության մեկ մեքենայական բառը պարունակում է 64 բիթ։ OCaml-ում `int` տիպի արժեքը ներկայացնելու համար օգտագործվում է դրանցից 63-ը։ Այդքան բիթով կարելի է ներկայացնել 2<sup>63</sup> տարբեր ամբողջ թիվ, որոնց կեսը բացասական է։ Այստեղից էլ ստացվում է վերը նշված միջակայքը։

Մնացած 1 բիթը հիմնականում օգտագործում է OCaml-ի **հիշողության ավտոմատ կառավարման մեխանիզմը** (_garbage collector_)։ Այն ավտոմատ կերպով ազատում է հիշողության այն հատվածները, որոնք ծրագիրն այլևս չի օգտագործում։ Մեխանիզմը պետք է ամբողջ թվերը տարբերի ցուցիչներից։ Ցուցիչը հիշողության մեջ պահվող մեկ այլ տվյալի հասցեն է։ Այդ պատճառով OCaml-ը [n թիվը պահում է 2n + 1 տեսքով](https://github.com/ocaml/ocaml/blob/5.5/runtime/caml/mlvalues.h)։ Այդպիսի ներկայացման մեջ ամբողջ թվի կրտսեր (ամենաաջ) բիթը միշտ 1 է, իսկ ցուցիչինը՝ 0։ Այս տարբերակիչ նշանը կոչվում է **պիտակ** (_tag_), իսկ այդպես ներկայացված ամբողջ թվերը՝ **պիտակավորված ամբողջ թվեր** (_tagged integers_)։ Մեկ բիթ հատկացնելով այս նշանին՝ OCaml-ը [ամբողջ թիվը պահում է հենց մեքենայական բառում](https://ocaml.org/manual/latest/intfc.html#ss:c-int)՝ առանց լրացուցիչ հիշողություն հատկացնելու։ 32-բիթանոց համակարգերում `int` տիպի արժեքի համար մնում է 31 բիթ։

Ինչո՞ւ է OCaml-ն ընտրել հենց այս ձևը։ Հիշողության ավտոմատ կառավարման մեխանիզմի աշխատանքը հեշտացնելու համար թվերը կարելի է պահել նաև այլ կերպ՝ հիշողության առանձին բլոկում, իսկ ծրագրում փոխանցել միայն այդ բլոկի հասցեն։ Այս եղանակը կոչվում է **փաթեթավորում** (_boxing_)։ Python-ում, օրինակ, [յուրաքանչյուր ամբողջ թիվ առանձին օբյեկտ է](https://docs.python.org/3/c-api/long.html#integer-objects)։ Սակայն այդ դեպքում թվի հետ ամեն գործողությունից առաջ ծրագիրը պետք է նախ հասցեով գտնի այն, իսկ նոր թվի համար սովորաբար հատկացնի նոր բլոկ։ OCaml-ի `int` տիպի արժեքին այս քայլերը պետք չեն․ թիվն արդեն մեքենայական բառի մեջ է, և պրոցեսորը կարող է անմիջապես աշխատել դրա հետ։ Տարբերակիչ բիթի պատճառով անհրաժեշտ լրացուցիչ քայլերը շատ քիչ են․ x86 պրոցեսորների համար `ocamlopt` կոմպիլյատորը գումարումը վերածում է պրոցեսորի ընդամենը մեկ հրահանգի, հանումը՝ երկուսի, իսկ բազմապատկումը՝ մի քանիսի։ Ուստի OCaml-ում ամբողջ թվերը, [ընդհանուր առմամբ, ամենաքիչ ռեսուրս պահանջող և ամենաարագ արժեքներն են](https://dev.realworldocaml.org/runtime-memory-layout.html#distinguishing-integer-and-pointers-at-runtime)։ Ահա թե ինչու է OCaml-ը «զոհաբերում» հիշողության այդ մեկ բիթը։

### Գերլցում առանց նախազգուշացման

Ի՞նչ է տեղի ունենում, եթե արդյունքը դուրս է գալիս այս սահմաններից։

```ocaml
max_int + 1;;
```

```text
- : int = -4611686018427387904
```

OCaml-ը շարունակում է հաշվարկն առանց սխալի հաղորդագրության կամ բացառության։ Ինչպես ժամացույցի թվատախտակին 12-ին հաջորդում է 1-ը, այնպես էլ `max_int`-ին հաջորդում է `min_int`-ը։ Երբ հաշվարկի արդյունքը դուրս է գալիս տիպի սահմաններից, տեղի է ունենում **գերլցում** (_overflow_) և OCaml-ն [այդ մասին չի զգուշացնում](https://ocaml.org/manual/latest/api/Int.html)։ Օրինակ Python-ում [ամբողջ թվերի չափը նախապես սահմանափակված չէ](https://docs.python.org/3/library/stdtypes.html#numeric-types-int-float-complex), իսկ OCaml-ում այդպիսի սահման կա։ Հաշվի առեք դա, երբ թվերը կարող են շատ մեծանալ, հատկապես՝ բազմապատկելիս։ Այս սահմանն արագ ու արդյունավետ `int`-ի գինն է։ Իսկ եթե ծրագրին իսկապես պետք են շատ մեծ ամբողջ թվեր, կարելի է օգտագործել [Zarith](https://github.com/ocaml/Zarith) գրադարանը, որում ամբողջ թվերի չափը նախապես սահմանափակված չէ։

## Ամփոփում

- Ամբողջ թվի լիթերալում կարելի է ընդգծման գծիկներ դնել, օրինակ՝ `1_000_000`։ `*`, `/` և `mod` օպերատորներն ավելի բարձր առաջնահերթություն ունեն, քան `+`-ն ու `-`-ը։ Այստեղ նույն առաջնահերթության օպերատորները խմբավորվում են ձախից աջ։
- Արժեքից հետո գրված `-` նշանը նշանակում է հանում։ Ուստի բացասական արգումենտի դեպքում գրեք `abs (-7)`։ OCaml-ը `abs -7` գրառումը կընկալի որպես հանում։
- Ամբողջ թվերով բաժանման արդյունքը կլորացվում է դեպի զրո։ Եթե `x mod y` մնացորդը զրոյից տարբեր է, այն ունի `x`-ի նշանը։ Զրոյի վրա բաժանելիս առաջանում է `Division_by_zero` բացառություն։
- 64-բիթանոց համակարգում `int` տիպի արժեքը ներկայացվում է 63 բիթով։ Մեկ բիթը հիշողության ավտոմատ կառավարման մեխանիզմի համար ծառայում է որպես տարբերակիչ նշան։ `min_int` և `max_int` սահմաններից որևէ մեկն անցնելիս հաշվարկը շարունակվում է միջակայքի մյուս ծայրից՝ առանց նախազգուշացման։

## Վարժություններ

### 1. Թվաբանական գործողություններ ամբողջ թվերով

Կանխատեսեք, թե utop-ն ինչ արժեք և ինչ տիպ ցույց կտա յուրաքանչյուր անվան համար։

```ocaml
let a = 17 / 5;;
let b = 17 - 5 * 3;;
let c = -17 / 5;;
let d = 2 + 3 * 4 - 8 / 3;;
```

Ի՞նչ կստացվի `c`-ի դեպքում՝ `-3`, թե՞ `-4`։ Ինչո՞ւ։

### 2. Բաժանման մնացորդը և օպերատորների առաջնահերթությունը

Յուրաքանչյուր արտահայտության համար նշեք արժեքն ու տիպը կամ գրեք, թե ինչ սխալ է առաջանում։

- ա) `-23 mod 4`
- բ) `23 mod -4`
- գ) `100 - 7 mod 3 * 2`
- դ) `2 * 8 mod 3`
- ե) `7 mod 0`

Փակագծերով ցույց տվեք նաև, թե OCaml-ն ինչպես է խմբավորում գ) և դ) կետերի արտահայտությունները։ Յուրաքանչյուր գործողություն վերցրեք առանձին զույգ փակագծերի մեջ։

### 3. Մինուսի նշանը

Յուրաքանչյուր արտահայտության համար նշեք արժեքն ու տիպը կամ գրեք, թե ինչ սխալ է առաջանում։

- ա) `- -4`
- բ) `10 - -4`
- գ) `10--4`։ Սխալի հաղորդագրության մեջ OCaml-ը գրառման ո՞ր մասն է մատնանշում և ինչո՞ւ։
- դ) Մուտքագրեք `let y = 3;;`։ Ինչպե՞ս է OCaml-ը կարդում `5 -y` գրառումը՝ որպես հանո՞ւմ, թե՞ որպես կողք կողքի գրված երկու թիվ՝ `5` և `-y`։ Ի՞նչ արդյունք կստանաք։
- ե) `-y * -y`

### 4. Գերլցում

Պատասխաններում օգտագործեք `max_int`, `min_int` կամ փոքր թվեր։ 19-նիշանոց թվեր գրելու կարիք չկա։

- ա) `max_int + 1`
- բ) `min_int - 1`
- գ) `max_int * 2`։ Հաշվի առեք, որ `min_int + max_int` գումարը հավասար է `-1`-ի։ Ցույց տվեք, թե ինչպես ստացաք պատասխանը։
- դ) `- min_int`։ Մեկ նախադասությամբ բացատրեք, թե ինչու է ստացվում հենց այդ արժեքը։
- ե) Ի՞նչ է տեղի ունենում `max_int + 1` արտահայտությունը հաշվելիս, իսկ ի՞նչ՝ `1 / 0` արտահայտությունը հաշվելիս։ Տարբերությունը բացատրեք մեկ կամ երկու նախադասությամբ։

### 5. Ժամեր, րոպեներ և վայրկյաններ

Մուտքագրեք `let total = 10_000;;`։ Այստեղ `total`-ը վայրկյաններով արտահայտված տևողությունն է։

- ա) `/` և `mod` օպերատորներով հաշվեք լրիվ ժամերի քանակը (`hours`), ապա մնացած ժամանակն արտահայտեք րոպեներով (`minutes`) և վայրկյաններով (`seconds`)։ Միջանկյալ և վերջնական արդյունքներից յուրաքանչյուրի համար գրեք առանձին `let` կապակցում։
- բ) Ի՞նչ արժեք ունի `total / 60 * 60` արտահայտությունը։ Ինչո՞ւ այն ցույց չի տալիս լրիվ ժամերի քանակը։
- գ) Նույն երեք արժեքները հաշվեք առանց `mod`-ի՝ օգտագործելով միայն `/`, `*` և `-` օպերատորները։ Ստուգման համար հաշվեք `hours * 3600 + minutes * 60 + seconds`։ Արդյունքը պետք է հավասար լինի `total`-ին։

### 6. Թվի թվանշանների գումարը

Մուտքագրեք `let n = 4_096;;`։ Օգտագործելով միայն `/` և `mod` օպերատորները՝ առանձնացրեք թվի բոլոր թվանշանները և յուրաքանչյուրին առանձին անուն տվեք։ Այնուհետև հաշվեք թվանշանների գումարը։

### 7. Շաբաթվա օրերը

Շաբաթվա օրերը համարակալված են 0-ից (երկուշաբթի) մինչև 6-ը (կիրակի)։ Ենթադրենք՝ այսօր չորեքշաբթի է։ Մուտքագրեք `let today = 2;;`։

- ա) Շաբաթվա ո՞ր օրը կլինի 100 օր անց։
- բ) Կանխատեսեք `(today - 10) mod 7` արտահայտության արժեքը։ Ինչո՞ւ այդ թիվը չի համապատասխանում շաբաթվա օրերից որևէ մեկին։
- գ) Գրեք արտահայտություն, որը ցույց կտա, թե շաբաթվա որ օրն էր 10 օր առաջ։ Այն միշտ պետք է տա օրվա վավեր համար՝ 0-ից 6-ը ներառյալ, և ճիշտ աշխատի նաև այն դեպքում, երբ `10`-ի փոխարեն գրեք `1000`։ Կարող եք `mod`-ը կիրառել մեկից ավելի անգամ։

### 8. Ե՞րբ կգերլցվի նանովայրկյանների հաշվիչը

Ինչպես հոդվածի օրինակներում, այստեղ էլ ենթադրեք, որ ծրագիրն աշխատում է 64-բիթանոց համակարգում։ Այն `int` տիպով պահում է 1970 թվականի հունվարի 1-ից անցած նանովայրկյանների քանակը։ Մեկ նանովայրկյանը վայրկյանի մեկ միլիարդերորդ մասն է։

Մոտավորապես ո՞ր թվականին կգերլցվի հաշվիչը։ Նահանջ տարիները հաշվի մի առեք։ Հաշվարկը կատարեք քայլ առ քայլ՝ միջանկյալ արդյունքներին հերթով տալով `seconds`, `days` և `years` անունները։

### 9. Երբ միջնակետի հաշվարկը սխալ արդյունք է տալիս

Մուտքագրեք `let low = max_int - 10;;` և `let high = max_int;;`։

- ա) Ի՞նչ նշան կունենա `(low + high) / 2` արտահայտության արժեքը։ Հիմնավորեք ձեր կանխատեսումը։
- բ) Ենթադրեք, որ `low`-ն ու `high`-ը ոչ բացասական թվեր են, և `low`-ն չի գերազանցում `high`-ը։ Գրեք արտահայտություն, որն առանց գերլցման կհաշվի այդ թվերի միջին թվաբանականի ամբողջ մասը։ Ստուգեք, որ վերը տրված արժեքների դեպքում ստացվում է `max_int - 5`։

Երկուական որոնումը կարգավորված տվյալներում արժեք է փնտրում՝ ամեն քայլում այն համեմատելով դիտարկվող հատվածի միջին տարրի հետ։ Java-ի ստանդարտ գրադարանում այդ տարրի ինդեքսը հաշվում էին `(low + high) / 2` արտահայտությամբ։ [Այս սխալը կոդում մնաց մոտ ինը տարի](https://research.google/blog/extra-extra-read-all-about-it-nearly-all-binary-searches-and-mergesorts-are-broken/)։
